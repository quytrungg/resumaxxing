# Phase Plan — OpenCode Go provider (alongside Opencode Zen)

> Required by AGENTS.md rule 1: this plan must exist and be confirmed by the
> user before any implementation code is written.

## Goal

The Settings page can save one Opencode credential, labelled **Opencode Zen**
(`opencode_key`, base `https://opencode.ai/zen`). OpenCode Go is a *separate*
subscription with its own API key and its own endpoint, so a Zen key cannot be
reused for it. Add **Opencode Go** as a first-class provider next to Zen: same
UI row (key / base URL / default model / Test / delete), its own encrypted key
column, its own default base URL `https://opencode.ai/zen/go`, and selectable in
the New Review modal like every other provider.

Verified before planning: `GET https://opencode.ai/zen/go/v1/models` with a Go
key returns 200 and 30 models (`glm-5.3`, `kimi-k3`, `grok-4.7`,
`deepseek-v4.1-flash`, …) — the same `{base}/v1/models` shape the existing
catalog helper already uses. No key is echoed anywhere in this plan.

## Success criteria

- [ ] `alembic current` is the new head and `\d user_settings` shows
      `opencode_go_key`, `opencode_go_base_url`, `opencode_go_model`.
- [ ] `PUT /api/settings {"opencode_go_key": …, "opencode_go_base_url": …,
      "opencode_go_model": …}` → `GET /api/settings` returns a masked
      `opencode_go_key` plus the base URL and model; the Zen fields are
      unaffected.
- [ ] `POST /api/settings/providers/models {"provider": "opencode_go"}` → 200
      with 30 models (saved key path), and with no key → 400
      `"Add a Opencode Go API key first."`
- [ ] `DELETE /api/settings/providers/opencode_go` clears only the Go key /
      base / model and drops `llm_provider` to `mock` only when Go was active.
- [ ] `llm.llm_score(...)` with `provider="opencode_go"` reaches
      `{base}/v1/chat/completions` with the Go key and a stable
      `x-opencode-session` header (the endpoint 400s without it) and returns an
      integer score — proved against a stub server, then against the real
      endpoint using an in-memory settings object (no key written to the DB).
- [ ] Settings UI: "Opencode Go" appears in the provider dropdown, prefetches
      its model list, saves as its own row with a mask, can be made active and
      deleted; "Opencode Zen" keeps working unchanged.
- [ ] New Review modal lists "Opencode Go" (enabled once a Go key is saved) and
      pins it on the created review.
- [ ] `POST /api/reviews` with `llm_provider: "opencode_go"` is accepted;
      an unknown provider is still rejected.

## Phases

### Phase 1 — Data model + migration
- Files: `backend/app/models.py`,
  `backend/alembic/versions/<new>_opencode_go_settings.py`
- Changes: add `opencode_go_key` (Text), `opencode_go_base_url` (String 500),
  `opencode_go_model` (String 100) to `UserSettings`; update the
  `llm_provider` comment. Migration is autogenerated, three `ADD COLUMN`s,
  nullable, with a working downgrade.
- Verify: `.venv/bin/alembic upgrade head` → `alembic current` at new head,
  `psql -c '\d user_settings'` shows the columns, existing row untouched.

### Phase 2 — Backend provider wiring
- Files: `backend/app/services/model_catalog.py`, `backend/app/schemas.py`,
  `backend/app/routers/settings.py`, `backend/app/services/llm.py`,
  `backend/app/routers/reviews.py`
- Changes:
  - `model_catalog.PROVIDERS["opencode_go"]` = label `Opencode Go`, key
    `opencode_go_key`, base `opencode_go_base_url`, model `opencode_go_model`,
    default base `https://opencode.ai/zen/go`, default model `glm-5.3`.
  - `SettingsIn` / `SettingsOut` gain the three optional fields.
  - `settings.py`: add the key field to `KEY_FIELDS`, the other two to
    `NULLABLE_FIELDS`, and emit them from `_settings_out`.
  - `llm.py`: `_chat_completion` handles `opencode_go` through the same
    OpenAI-compatible branch and resolves the key from
    `PROVIDERS[provider]["key_field"]` instead of the current
    ollama/opencode conditional (one code path, no per-provider ifs).
  - `reviews.LLM_PROVIDERS` adds `opencode_go`.
- Verify: curl the settings round-trip, model listing, delete, and a
  `POST /api/reviews` validation check (Phase 2 verification section).

### Phase 3 — Frontend
- Files: `frontend/src/llmProviders.js`, `frontend/src/pages/SettingsPage.jsx`
- Changes: one `PROVIDERS` entry (`value: 'opencode_go'`, label
  `Opencode Go`, the three field names, default base
  `https://opencode.ai/zen/go`, default model `glm-5.3`, placeholders
  `Opencode Go API key` / `https://opencode.ai/zen/go`). Everything else
  (dropdown, prefetch loop, configured rows, Test, delete, New Review modal,
  model picker) is already driven by that list, so no component logic changes;
  only the card's descriptive sentence is widened to mention Go.
- Verify: browser — Go row added with mask, Test → "Connected · 30 models",
  activate, delete; Zen unaffected; New Review modal shows Go with its models;
  dark/light and ~760 px layouts still render.

### Phase 4 — Docs
- Files: `DOCS.md`
- Changes: provider table (`opencode_go` row), default-model sentence
  (`glm-5.3`), schema blurb, and the API reference's `llm_provider`
  enumeration.
- Verify: read-back of the edited sections; no stale `opencode`-only wording.

## Out of scope

- Renaming or re-labelling the existing `opencode` (Zen) provider, its columns,
  or its default model — Zen rows and pinned reviews must keep working.
- Migrating an existing Zen key into the Go provider, or sharing one key.
- Anthropic-style Go routes (`/inference/go/anthropic/v1/messages`): reviews keep
  using the OpenAI-compatible `/v1/chat/completions` path. The required
  `x-opencode-session` header is sent (a CV+JD hash); identifying user-agent
  headers and any other Go-specific request shaping are out of scope.
- Per-provider timeouts, retries, streaming, model pricing, or usage caps.
- Any change to the `mock` heuristic, scoring, or export paths.

## Database impact

One Alembic migration adding three nullable columns to `user_settings`
(`opencode_go_key`, `opencode_go_base_url`, `opencode_go_model`). No data
backfill, no ad-hoc DDL; `alembic_version` ends at the new head.
